### 32. 멀티태스크(멀티프로세스)와 멀티스레드를 비교하시오.

- **멀티태스킹**
    - 서로 독립적인 프로세스가 동시의 각자의 작업을 수행하는 방식이다.
    - 각 프로세스는 독립적인 메모리 공간을 가지며 데이터를 주고 받기 위해 프로세스 간 통신을 사용한다.
    - 프로세스는 서로 독립적이기 때문에, 한 프로세스의 작업이 다른 프로세스의 실행을 방해하지 않는다.

- **멀티스레드**
    - 하나의 프로세스 내부에서 여러 개의 스레드가 동시에 작업하는 방식이다.
    - 메모리나 파일과 같은 시스템 자원을 공유한다.
    - 프로세스가 비정상적으로 종료되면 그 안에 있는 모든 스레드도 강제 종료된다.

### 33. 멀티스레드의 장점을 설명하시오.

- **자원 공유**
    - 하나의 프로세스 내부에서 여러 스레드가 자원을 공유해 낭비를 최소화할 수 있다.

- **문맥 교환 효율적** 
    - 문맥 교환 시 변경할 정보가 상대적으로 적어 속도가 빠르고, 프로세스 간 통신 없이도 변수를 통해 데이터를 주고받을 수 있어 통신 비용이 감소한다.

- **응답 속도 향상**
    - 입출력 담당 스레드만 대기 상태가 되고, 나머지 스레드는 계속 실행할 수 있어 응답 속도가 향상된다.

- **적응성 향상**
    - 여러 개의 코어에 스레드를 분배하여 멀티코어 환경을 최적화할 수 있다.

### 34. 멀티스레드의 모델을 설명하시오.

- **1 to N 모델: 사용자 스레딩**
    - 라이브러리 수준에서 스레드를 구현하는 방식이며, 스레드가 커널의 직접적인 개입 없이 동작한다.
    - 커널의 개입 없이 스레드를 전환하기 때문에 낮은 문맥 교환 비용이 이점이다.
    - 커널 스레드가 대기 상태에 들어가면 모든 사용자 스레드가 멈춘다.
    - 멀티코어 활용이 불가능하다.

- **1 to 1 모델: 커널 스레딩**
    - 하나의 사용자 스레드가 하나의 커널 스레드와 연결되는 모델이다.
    - 하나의 스레드가 멈춰도 다른 스레드는 계속 실행할 수 있다.
    - 커널이 직접 스레드를 관리하기 때문에 문맥 교환 시 오버헤드가 발생한다.
    - 운영체제가 스레드를 여러 CPU에 분산하여 실행할 수 있다.

- **M to N 모델: 멀티레벨 스레딩**
    - 사용자 스레딩과 커널 스레딩을 혼합한 방식이다.
    - 하나의 커널 스레드가 대기 상태일 때 다른 커널 스레드가 대신 작업하여 사용자 스레드보다 유연하게 작업을 처리할 수 있다.
    - 문맥 교환 시 오버헤드가 있어 사용자 스레드만큼 빠르지 않다.
    - 사용자 스레드와 커널 스레드의 혼합 모델이므로 스케줄링 및 동기화가 복잡해질 수 있다.

### 35. 프로세스 간 통신에 대하여 설명하시오.

- 프로세스와 스레드는 독립적으로 실행되지만, 협업을 위해 데이터를 주고받아야 한다.
- 스레드는 하나의 프로세스 내에서 자원을 공유하기 때문에 스레드 간 통신이 비교적 간단하다.
- 서로 다른 프로세스는 각자 독립적인 메모리 공간을 가지므로 데이터를 공유하기 어렵다.
- 따라서 프로세스가 서로 데이터를 주고 받는데, 이를 프로세스 간 통신이라고 부른다.

### 36. 통신 방향에 따른 통신에 대하여 설명하시오.

- **단방향 통신**
    - 한쪽에서만 데이터를 보내고, 반대쪽에서는 받을 수만 있는 통신 방식이다.

- **양방향 통신**
    - 양쪽에서 데이터를 자유롭게 주고받을 수 있는 통신 방식이다.

- **반양방향 통신**
    - 양방향으로 통신할 수 있지만, 동시에 송수신은 불가능하여 특정 시점에는 한쪽으로만 통신한다.

### 37. 파일 포인터의 특징을 설명하시오.

- 파일에서는 파일 포인터가 작업 위치를 가리킨다.
- 현재 파일에서 읽거나 쓸 위치를 나타내며, 파일의 시작에서부터 얼마나 떨어져 있는지를 바이트 단위로 나타낸다.
