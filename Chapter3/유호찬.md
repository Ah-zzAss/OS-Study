## 프로세스의 개념과 상태

### 프로세스의 개념

#### 프로세스와 프로그램

- 프로세스: 프로그램이 실행되어 메모리에 올라온 상태를 의미한다.
- 프로그램: 특정 데이터를 처리하는 방법과 절차를 정리한 파일

프로그램을 실행한다는 것은 프로그램의 코드가 메모리에 올라와 프로세스가 된다는 것을 의미

#### 프로세스의 구조

메모리에서 프로세스의 실행 코드는 크게 코드 영역과 데이터 영역으로 나뉜다.

- 코드 영역: 프로그램의 본문에 해당하는 영역으로 텍스트 영역이라고도 부른다.
- 데이터 영역: 편집 중인 데이터가 저장되는 영역. 데이터 영역은 다시 정적 데이터 영역, 힙 영역, 스택 영역으로 나뉜다.
    - 정적 데이터 영역: 정적변수나 전역변수와 같은 변수가 저장되는 영역
    - 힙 영역: 실행 중 동적으로 할당된 변수가 저장되는 영역
    - 스택 영역: 함수 호출과 관련된 데이터가 저장되는 영역

### 프로세스의 상태

운영체제는 실행 중인 각 프로세스를 관리하기 위해 프로세스별로 상태 정보를 프로세스 제어블록(PCB)에 저장한다.

위와 같은 프로세스 상태 전이도에 따라 동작한다.

- 생성 상태: 프로그램이 메모리에 올라와 프로세스가 생성된 상태
- 준비 상태: 운영체제가 프로세스에 CPU가 할당되기를 기다리는 상태이다. 어떤 PCB를 실행 상태로 보낼지 결정하는 과정을 디스패치라고 부른다.
- 실행 상태: CPU를 할당받아 실제 작업을 수행하는 상태
- 대기 상태: 실행 중인 프로세스가 입출력을 요청한 후에 기다리는 상태
- 완료 상태: 프로세스가 모든 작업을 완료한 상태

위와 같은 상태를 활성 상태라 하고 반면에 프로세스가 실행되지 않거나 메모리에서 제거된 상태를 비활성 상태라고 한다.

## 프로세스 제어 블록과 문맥 교환

### 프로세스 제어 블록

#### 프로세스 제어 블록의 필요성

과거 일괄 작업 시스템에서는 한 번에 1개의 프로세스만 실행했기 때문에 PCB의 필요성이 크지 않았다.

현재는 멀티태스킹을 수행하기 때문에 PCB에 관련 정보들을 기록해야 한다.

모든 프로세스는 고유한 PCB를 가지며 관련 정보를 저장한다.

#### 프로세스 제어 블록의 구성요소

- 포인터: 다음 PCB와 연결하는 역할
- 프로세스 상태: 프로세스의 현재 상태를 저장하는 필드
- 프로세스 구분자(PID): 각 프로세스를 구별하는 고유한 구분자
- 프로그램 카운터(PC): 다음에 실행할 명령어의 위치를 저장하는 필드
- 프로세스 우선순위: 프로세스의 중요도에 따라 우선순위를 부여한다.
- 각종 레지스터 정보: 사용하던 레지스터의 값을 저장한다.
- 메모리 관리 정보: 사용하던 메모리 주소 정보 저장
- 할당된 자원 정보: 사용하던 자원 목록을 저장
- 계정 정보: 컴퓨터를 사용하면서 발생한 모든 정보를 저장
- 부모 프로세스 구분자와 자식 프로세스 구분자: 부모 프로세스 구분자(PPID)아 자식 프로세스의 구분자(CPID)를 저장

### 문맥 교환

#### 문맥 교환의 개념

CPU를 사용하던 프로세스를 중단하고 새로운 프로세스로 전환하는 과정을 말한다.

#### 문맥 교환 과정

1. 프로세스 P1이 할당된 작업 시간을 다 사용한다.
2. P1의 PCB에 현재까지 작업 결과를 저장하고 P1의 PCB가 준비상태로 옮겨진다.
3. 준비 상태에 있던 프로세스 P2의 PCB가 실행 상태로 진입한다.
4. 레지스터를 P2의 PCB에 저장되어 있는 값으로 변경한다.
5. P2의 작업을 진행한다.

#### 문맥 교환과 타임 슬라이스의 크기

타임 슬라이스가 너무 크면 하나의 프로세스가 오래 실행되어 다른 프로세스의 대기 시간이 길어진다.

너무 작으면 실제 작업 시간보다 문맥 교환에 더 많은 시간을 낭비하게 된다.

그래서 적당한 값으로 설정해야한다. 유닉스에서는 10~200MS로 설정한다.


## 프로세스 계층 구조

### 프로세스 계층구조의 필요성

#### 가비지 컬렉션

불필요한 프로세스를 정리하고 자원을 회수하는 것

부모-자식 관계로 묶어서 부모 프로세스가 자식 프로세스를 생성하고, 자식 프로세스가 종료되면 부모 프로세스가 자식프로세의 자원을 회수한다.

### 프로세스 생성 시스템 호출

#### fork()

기존의 프로세스로부터 자식 프로세스를 생성하는 시스템 호출

fork()를 실행하면 새로운 자식 프로세스가 생성되며 기존 프로세스는 부모 프로세스가 된다.

병렬 처리 구현, 빠른 프로세스 생성, 손쉬운 자원 상속, 편리한 자원 회수 장점이 있다.

### 프로세스 재사용 시스템 호출

#### exec()

기존 프로세스에서 코드만 새로운 프로그램으로 변경하는 시스템 호출

기존의 pcb를 유지하면서 기존의 코드 영역이 새로운 코드로 완전히 교체된다.

### 프로세스 동기화

#### wait()

자식 프로세스가 종료되기 전에 부모 프로세스가 먼저 종료되면 자식 프로세스는 고아 프로세스가 된다.

이를 방지하기 위해 부모 프로세스에서 wait()을 호출해야 한다.

wait()은 자식 프로세스가 끝나서 종료 신호를 보낼 때 까지 기다리는 함수이다.
